# MARU

A discovery-led mobile client for the public [AniList GraphQL API](https://graphql.anilist.co),
built from the design handoff in `../design_handoff_maru_anime_tracker`. One Expo / React Native
codebase ships to both the App Store and Play Store.

## Running it

```sh
npm install
npx expo start          # then press i / a, or scan with Expo Go
npx expo run:ios        # native debug build (needs full Xcode + CocoaPods)
npx expo run:android    # native debug build (needs the Android SDK)
```

`ios/` and `android/` are generated by `npx expo prebuild` — regenerate them with
`npm run prebuild:clean` after changing `app.json` rather than editing them by hand.

## Sign-in

AniList issues implicit-grant tokens to a registered client. Create one at
<https://anilist.co/settings/developer> with **`maru://auth`** as the redirect URL, then add
its id to `app.json`:

```json
{ "expo": { "extra": { "anilistClientId": "12345" } } }
```

Without it the app still runs: **Browse as guest** works everywhere, and tracking
affordances (+1, list pills, the progress sheet) stay hidden, exactly as the handoff specifies.

## How it is put together

| Area | Where |
|---|---|
| The twelve design tokens and the three themes | `src/theme/tokens.ts` |
| Runtime theme switching, persistence, match-system | `src/theme/ThemeProvider.tsx` |
| Type helpers mirroring the design's CSS `font:` shorthand | `src/theme/type.ts` |
| GraphQL client, queries, typed hooks | `src/api/` |
| Auth (AniList OAuth + SecureStore) | `src/state/auth.tsx` |
| Media list cache — the source of truth for progress and score | `src/state/listCache.tsx` |
| Screens | `app/` (expo-router) |

### Theming

Every surface reads from twelve tokens; a theme is one override block. Accents are authored
in OKLCH in the design and converted here with chroma-reduction gamut mapping, so they hold
the same lightness and chroma and differ only in hue. Adding a theme means adding one entry
to `THEMES` — nothing else in the app hardcodes a colour.

### The list cache

`SaveMediaListEntry` mutations are optimistic and keyed by media id. Because every screen
reads progress and score from the same cache, a `+1` on My List moves Discover's
continue-watching bar without a refetch; a failed mutation reverts and raises a toast.

### Platform differences

Same tokens, same content, different chrome. `Platform.OS === 'android'` selects the
Material 3 shell: a pill search field instead of the editorial header, the poster wall in
place of the spotlight, larger radii, 3px underlined tabs, circular filled `+1` buttons,
list rows as separated cards, and the extended **+ Track** FAB.
